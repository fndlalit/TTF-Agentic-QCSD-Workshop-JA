# ワークショップ用コンテナ: Codespaces またはローカルの Docker

**2026年11月12日** の Tokyo Test Fest チュートリアルで、README の手動セットアップの代わりに使える方法です。同じアプリと演習、**公開されている最新の AQE**、ローカル embedder **4.2.0** を使います。Node 22 は AQE のエンジン要件を満たします。このコンテナと手動セットアップは、どちらも最新リリースを使います（2026年11月6日の検証時点で 3.15.18）。

## GitHub Codespaces

1. リポジトリを開き、**Code → Codespaces → Create codespace on main** を選びます。
2. コンテナのビルドとセットアップが終わるまで待ちます。可能なら、4コア・8 GB RAM のマシンを選んでください。ご自身の GitHub Codespaces の無料枠 / 課金が適用されます。
3. ターミナルで次を実行します。

   ```bash
   bash .devcontainer/prepare-workshop.sh
   bash .devcontainer/verify.sh
   node .devcontainer/verify-mcp.mjs
   npm run test:run
   ```

4. **コンテナの中で** コーディングエージェントにサインインします。Claude Code なら `claude` を実行し、ワークスペースを信頼して、`agentic-qe` MCP サーバーを承認します。Codex CLI も入っています。Codex を選ぶ場合は、意図して `aqe init --auto --with-codex` を実行し、その後 `codex login --device-auth` を実行してください。この設定手順は手動です。再起動で、選んだエージェントの設定が上書きされないようにするためです。他のエージェントは、README の対応するセットアップのフラグと、各自の認証を使います。
5. **LAB.md** を開きます。準備コマンドが、演習0をすでに実行し、チェックアウト用のシードパターン6件を読み込み済みです。出力をベースラインとして確認してください。

最初の準備では、埋め込みモデルをダウンロードします。**会場に着く前に** 行ってください。初回のセットアップも、エージェントの利用も、オフラインでは動きません。インデックス作成と埋め込みはコンテナの中で動きます。Codespaces では、GitHub 側のマシンで動くという意味です。エージェント演習は、引き続き、選んだモデルプロバイダーとそのトークンを使います。

## ノート PC 上の DevPod + Docker

Docker Desktop（または Linux の Docker デーモン）を起動し、DevPod をインストールしてから、次を実行します。

```bash
git clone https://github.com/fndlalit/TTF-Agentic-QCSD-Workshop-JA
cd TTF-Agentic-QCSD-Workshop-JA
devpod provider add docker   # 初回のみ。設定済みなら不要
devpod up . --provider docker --id ttf-70-percent
```

新しいワークスペースで、同じ準備、検証、サインインの手順を実行します。イメージは Linux の amd64 と arm64 に対応しています（Apple Silicon は Linux コンテナを使います）。amd64 エミュレーションの強制はありません。8 GB 以上の RAM と 32 GB のディスクを確保してください。別の方法として、このクローンを VS Code で開き、Dev Containers 拡張機能を入れて、**Dev Containers: Reopen in Container** を選ぶこともできます。

## 対象アプリを実行する

```bash
npm run dev -- --hostname 0.0.0.0 --port 3000
```

エディタの Ports ビューで、ポート **3000** を開きます。Codespaces では、公開範囲を **Private** のままにしてください。転送される URL は HTTPS です。ローカルの DevPod では、転送された localhost のアドレスを使います。ノート PC でポート 3000 がすでに使われている場合は、別のローカル転送ポートを選んでください。転送設定を更新せずに、アプリのポートを変更しないでください。

カタログ、カート、テスト、静的解析、QCSD 演習に、**Stripe キーは不要** です。実際のチェックアウトには、ご自身の Stripe **テストモード** の公開可能キーとシークレットキーが必要です。git 管理外の `.env.local` ファイル（`.env.example` を参照）か、Codespaces の secrets に設定し、設定後に Next.js を再起動してください。プレースホルダーのキーは、動作する認証情報ではありません。この意図的に欠陥のあるアプリに、本番キーや実際のカード情報を使わないでください。キーがない場合、Stripe のチェックアウト / 決済ルートは失敗するのが正常です。環境チェックが緑でも、決済が完了したことは意味しません。

商品画像は外部のプレースホルダーホストから読み込まれ、表示されないことがあります。注文はプロセスのメモリ上にあり、Next.js を再起動すると、デモの注文は消えます。Kafka は、注入された送信関数を使うテスト用の抽象なので、ワークスペースにブローカー、PostgreSQL、Redis、Rust、Docker ソケットは不要です。

## セットアップが変更するものと、保持するもの

- イメージには、最新の AQE、Claude Code、Codex、GitHub CLI と、Transformers 4.2.0 が入ります。ベースの Node 22 イメージは、アップストリームのメンテナンス更新を受け取ります。
- `post-create.sh` は、キャッシュされた Docker イメージを使っていても、AQE、Claude Code、Codex、GitHub CLI を最新に更新します。コミット済みのアプリのロックファイルに対して `npm ci` を実行し、`.agentic-qe` がない場合にのみ AQE を初期化します。`.env.local` は、存在しない場合にのみ、空の非公開ファイルとして作成します。再開時に、依存パッケージのインストールやメモリの書き換えは行いません。
- `prepare-workshop.sh` は、初回に明示的に実行する操作です。`src/` のインデックス作成、埋め込みモデルのウォームアップ、シードの import を行います。検証に成功すると、マーカーが作られ、以降の実行は何もしません。これらの書き込みの前にタイムスタンプ付きの SQLite バックアップを作り、後で整合性を確認します。既存のデータは消しません。
- `verify.sh` は、ツール、演習用の資産、グラフ内のすべてのソースファイル、埋め込み付きのシードパターン6件、既存のデータベースを、読み取り専用で確認します。テストとカバレッジは別に実行してください。検証が、有料のエージェント演習を実行することはありません。
- レポートと AQE の SQLite データベースは、再起動をまたいでワークスペースに残ります。Codespace や DevPod のワークスペースを削除する前に、作業内容をバックアップ / エクスポートしてください。コンテナのホームにキャッシュされたモデルは、再ビルド後に、再度ダウンロードが必要になることがあります。

Transformers は、README に書いたものと同じ、明示的なローカル埋め込みのオプトインです。依存関係のアドバイザリに関する注意も同じです。ポリシーで禁止されている場合は、このデフォルトのイメージではなく、信頼できる埋め込みエンドポイントを使う手動セットアップを使ってください。

## トラブルシューティング

- **`.agentic-qe` が不完全:** セットアップは、修復や削除をせずに停止します。ファシリテーターに調べてもらってください。セットアップのチェックを緑にするために、学習データベースを削除してはいけません。
- **import が `Imported: 0` と表示する:** TROUBLESHOOTING.md を参照してください。権威あるストアは SQLite です。誤解を招くその import カウンターではなく、実際のシードパターン6件を確認してください。
- **モデルのダウンロードに失敗する:** npm と Hugging Face へのプロキシ / ネットワークアクセスを確認し、準備を再実行してください。完了マーカーは、成功した後にだけ書かれます。
- **ホストでだけエージェントにサインインしている:** コンテナの認証情報は別です。コンテナ内のログインフローを使うか、ご自身のプロバイダーキーを Codespaces の secret として設定してください。
- **グラフの数が違う:** `aqe hg stats` は、このコンテナでは 110 ノード / 89 エッジ、手動セットアップ後は 140 ノード / 102 エッジと表示します。手動の `aqe init --auto` が自前のプロジェクトインデックスを実行するのに対し、コンテナは `--skip-code-index` を使うためです。設定されているプロバイダーによっても、数は変わり得ます。21個のソースファイルがすべてインデックスされていることを確認してください。1つの合計値を、すべてのファイルが含まれている証拠として扱わないでください。
- **Claude 以外のエージェントでの MCP メモリ:** TROUBLESHOOTING.md に、AQE 3.14.1 で観察された制限を書いています。新しいバージョンが同じ挙動だと決めつけないでください。選んだエージェントで想起を確認し、必要なら LAB.md のレポート経由の方法を使ってください。AQE 3.15.18 では、隔離した MCP ハンドシェイクが 91 個のツールを公開しましたが、検証済みの SQLite シードがあるにもかかわらず、メモリクエリは0件を返しました。MCP スモークチェックは、この制限を明示的に報告します。`--require-recall` を付けると失敗します。これはトランスポートの検証であり、お使いのエージェントの学びを演習5が想起できることの証明ではありません。Claude Code での完全な実行（3.15.18、手動セットアップ、2026年11月6日）では、演習1〜4が `learning` 名前空間に保存した4パターンを、演習5が実際に想起しました。シードの6パターンは、メモリクエリでは返りませんでした。
